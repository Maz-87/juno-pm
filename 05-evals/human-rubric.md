## What graders score

- **What you’re scoring:** Juno's feature request summary
- **Value proposition:** synthesise and summarise all existing feature requests into common themes based on their problem statements saving PMs time and effort.

## Dimensions

| Dimension | Question | Scale | 1 or No | 3 | 5 or Yes |
|---|---|---|---|---|---|
| Hallucinations (deal-breaker) | Is each problem statement supported by feature requests have a corresponding Slack or JIRA reference? | Yes / No | No hyperlink Hyperlink links to a 404 Hyperlink links to a deleted message/ticket | n/a | Hyperlink to an existing slack message Hyperlink to a JIRA ticket |
| Private Data (deal-breaker) | Is the supporting Slack or JIRA references publicly accessible? | Yes / No | Slack message is sent in as a direct message between users JIRA ticket is under a confidential/private project  | n/a | Slack message is sent in a public channel JIRA ticket is under a non-private project  |
| Accuracy | Is the data behind the problem statement reliable? | 1 to 5 | Client name included in the feature request, but with a one sentence explanation of the feature request. No additional context around problem statement or business impact. | Client name included in the feature request, some basic context of the problem and a one sentance feature request. | Client name included in the feature request, high degree of context around the proble statement |

## Calibration

- **How many answers you’ll score, and how often:** 10 requests per week
- **Who scores them with you:** myself and the other PM
- **What happens when two of you disagree:** If our scores differ by 2 or more, we will either go back to the source for additional context before including the request in the dataset, OR decide the information is sufficient and include the request in the dataset

## Pass bar

An average of 3 on the accuracy scale and a 'yes' to all other rubric questions

**Fails outright, whatever the average:**

- Hallucinations: any "no"
- Private Data: any "no"
